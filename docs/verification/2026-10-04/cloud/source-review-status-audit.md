# Source review progress repair

The earlier hands-on native cloud journey and iPad release capture showed an initial proposal count after that proposal had already been accepted. The source detail screen read the persisted extraction message rather than current saved report review states. Acceptance and rejection correctly saved report decisions; the misleading presentation was the defect.

`SourceReviewStatus` now derives the source-specific pending count and reviewed patient report count from the current claim records. `SourceDetailView` uses this presentation each time observable store state changes. No evidence, processing-message history, working-text revision, report ID, rejected revision, or Keychain value is rewritten. This also handles an older persisted source with `needsReview` while all actual reports have already been reviewed.

Only successful review states (`needsReview` and `complete`) receive the current progress summary. Failed, cancelled, interrupted, active-processing, unanalysed, and edited-evidence messages retain their recovery instructions. Exact known app-generated extraction count prefixes are removed from the successful-state detail, while the 200-item limit warning and unsupported FHIR resource disclosures remain visible. Canonical counts refer to reports saved in My Care, not independently verified or clinically current facts. Rejected history and accepted family/other-subject reports do not count as saved patient reports.
