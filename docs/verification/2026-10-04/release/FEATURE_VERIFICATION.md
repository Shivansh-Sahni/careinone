Updated October 4–5, 2026 during release preparation. This ledger distinguishes actual passing evidence from source inspection, historical verification, and unfinished release checks. It is not a declaration that every button, device, permission state, or clinical scenario has been verified. Candidate5 native/core/backend results and completed focused UI actions are recorded below. Candidate6 verifies its earlier compiled app snapshot; Candidate7 archive and ordinary native tests now verify the later scoped row and keyboard repairs, with whole UI and native cloud evidence recorded separately. Whole-device Candidate6 uses later test navigation repairs against the earlier Candidate5 app snapshot; the later authorized hit-area change requires Candidate7/scoped final-source proof. The earlier Candidate5 UI action contains a failure and is not an all-passing result. The native real-cloud workflow, physical-device checks and publication identity/signing remain separate gates.

The [screen/control inventory](SCREEN_CONTROL_INVENTORY.md) indexes all inspected view/component structures and source-owned controls, with line contexts and hashes in [control-inventory.json](control-inventory.json). The [navigation/control audit](NAVIGATION_AND_CONTROL_AUDIT.md) maps screen families to evidence, documents system-owned controls and current input/navigation concerns, and prevents source inspection from being mistaken for runtime verification.
