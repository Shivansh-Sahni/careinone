# Source disclosure recheck

Read-only source and release-material audit on October 5, 2026. Production changes, device tests, deployment and provider requests are outside this audit's scope. C7 failures and unsigned signing status remain unchanged.

## Material correction made

The [App Privacy worksheet](../../../../app-store/privacy-label-worksheet.md) previously described the gateway bearer credential as per-installation. The gateway actually hashes and checks its operator-configured token values, and a token can be reused across installations. The worksheet now says **operator-issued gateway access token, not necessarily unique per installation**. Separate installation tokens require operator provisioning. This change does not add enrollment, rotate credentials, or imply identity anonymity. The release-review notes already accurately describe operator-configured access and the absence of self-service public cloud enrollment.

## Confirmed actual behavior

- **Encrypted backup includes original evidence.** Both AppStore archive paths package original-file references and bytes, plus retained audio only when selected, within the aggregate attachment limit. The isolated asynchronous backup test explicitly preserves original bytes while excluding audio. Graph JSON exports are different: they contain saved text/records without original binary attachments or audio. The existing policy/support drafts and live HTML correctly distinguish these. Device/iCloud backup exclusion is a separate storage setting and is not a claim that user-created encrypted backups omit originals.
- **Cloud sends working text, source type and optional event date.** `CloudExtractor`'s encoded request also carries schema, consent and the approved provider-configuration fingerprint; it has no original-file/audio payload. The gateway bearer token travels in its Authorization header. Ephemeral URLSession rejects redirects and caches; raw server error bodies are not displayed. App consent and server configuration mismatch checking remain explicit. These facts support the current public text; they do not establish hosting or model retention beyond the separately documented controls.
- **Local operation history does not record clinical prose through current app operations.** `Audit` consists of UUID, timestamp, operation name and count. Current append sites use fixed operation strings and counts; there are no source quotations, notes or patient names in those event fields. The records/exports themselves still contain user content and must not be described as anonymous.
- **Recording remains local.** Selected photos/documents use local OCR; on-device Speech availability depends on permission, device and language. Microphone agreement/foreground behavior remains in the capture flow. The audio-session continuation repair is not a new remote transcription flow. C8 native lifecycle tests and the finalized first whole UI action show zero AVAudioSession warnings; physical hardware verification remains outstanding.
- **External copies remain user-managed.** Calendar uses write-only explicit export, local opaque receipt hashes and explicit extra-copy confirmation. Local edits/deletion do not recall Calendar events, system-share copies, backups or already transmitted provider requests. Public policy/support wording already includes these limits.
- **Review means reported meaning, not medical correctness.** Store description/review notes preserve user review, exact supporting evidence, unresolved conflicting reports, no diagnosis/prescribing/emergency monitoring, and no automatic clinic delivery. C8's verified source-status display counts current saved reports without making a new clinical-verification claim.
