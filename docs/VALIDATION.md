## Failures found and corrected

- Xcode’s installed SDK initially lacked its matching simulator runtime; installed and booted iOS 26.5.
- Simulator architecture mismatch in the generated project; Debug now builds the active architecture consistently with its local Swift package.
- Allergy category pluralization; fixed the real category label.
- UI automation originally tapped the confirmation label, leaving the native switch off; it now targets the actual switch and asserts that acceptance becomes enabled and completes before relaunch.
- Cancelled extraction could race a replacement run; per-source generation checks and regression tests now prevent stale writes.
- Appointment reminders could include superseded evidence or substitute source event dates; shared appointment selection and a deterministic reminder planner now exclude those cases.
- Source deletion could remove unrelated empty encounters; deletion is now scoped to the affected encounter.
- FHIR nonactive statuses and generic service categories could be overinterpreted; conservative status/category review and fixture tests now cover them.
- iOS 18 Vision returned Cyrillic lookalikes for Latin “CBC” even with English hints. The independent fast Latin recognizer handles that observed case. A language preference is available; automatic detection remains optional. OCR remains fallible and originals/review remain essential.
- Dark accessibility text exposed cramped horizontal cards; summaries/badges now adapt to vertical layouts.

## Physical iPhone validation still required

1. Open `CareInOne.xcodeproj`, configure the development team, select a connected iPhone on iOS 18+, enable Developer Mode, build/install/launch. Keep the bundle ID when upgrading an existing installation: changing it creates a separate app and data container. If a different ID is needed for a first development install, choose it before adding patient records. Confirm the native app opens without cloud settings.
2. Deny microphone permission and verify typed capture remains usable. Then grant access. For Record Visit, verify recording is disabled until the everyone-agreed toggle is enabled. Start, pause, resume, stop, and confirm the fixed recording banner and elapsed indicator.
3. Trigger a phone/audio interruption, lock the device, background the app, connect/disconnect Bluetooth/headphones, and confirm recording pauses and never continues silently. Force-quit during recording; reopen the saved audio draft and retry transcription or add a typed recap.
4. Test on-device Speech in supported and unsupported device/language combinations. Disable the network. Verify no remote Speech fallback occurs. Verify editable transcripts, supported transcript timestamps, default audio deletion after successful transcript persistence, optional retention, playback, and independent deletion.
5. Capture a photo of a synthetic medication label. Import a screenshot, native-text PDF, scanned PDF, UTF-8 and UTF-16 file, and the synthetic FHIR fixture. Check exact quotes/pages against the original. Import the same bytes again and verify only one source/file exists.
6. From Files/another app’s Open In flow, open supported evidence in CareInOne. Check security-scoped access and preservation when extraction fails. A separate share extension is not part of this build.
7. Turn on device authentication, background/reopen, cancel authentication, and use device-passcode fallback. Inspect app-switcher snapshots. Verify evidence/database files have complete protection and are excluded from backup; confirm locked-device file reads are unavailable.
8. Review each medication/allergy/instruction individually. Reject, edit numeric values/units/action/date, mark historical/uncertain/not-about-me, and choose a weak association. Verify related views update together and no provider discrepancy disappears merely because a patient reports what they take.
9. Create exact/approximate/unknown follow-through dates. Allow notifications and inspect generic lock-screen content. Edit/dismiss/complete/delete source and ensure pending reminders reconcile. Verify approximate dates never schedule exact reminders or claim overdue status.
10. Add a date-only appointment and a timed appointment to Calendar using explicit user actions. Confirm date-only events are all-day and the app requests write-only access. Check time zones/DST and the displayed duration before relying on an exported event.
11. Generate/share a Care Brief PDF and text. Inspect long multi-page content, synthetic labels, both conflicting doses, open loops, and source references. Export graph JSON and confirm the UI accurately states that attachments are excluded.
    Also prepare a selected visit packet: deselect private notes and identity fields, inspect quotes for identifying text, verify both sides of selected discrepancies, share to a real destination, and confirm the received copy matches the preview. Edit an outgoing message and confirm its old PDF cannot be shared until regenerated. Closing a draft does not save those edits to care memory.
12. Delete one source with claims, a conflict, and a loop; verify every derived view rebuilds. Independently delete audio. Remove synthetic demo data while preserving real sources. Delete all local data and confirm protected originals, credentials, notifications, and exports are removed.
13. Test VoiceOver, maximum accessibility text size, bold text, increased contrast, reduced motion, dark mode, landscape, small iPhones, and iPad. Confirm all review fields and actions remain reachable and quotes are readable.
14. Create a visit workspace and checkpoint with synthetic information. Save a recollection draft, force-quit, and reopen it. Save the recollection as evidence, review only the actual patient-entered passages, open the impact preview, then accept. Verify the saved comparison and shared text/PDF; no task should close merely because a recollection was saved. Repeat with only unanswered questions and an unknown visit date.
15. Make an encrypted backup containing a checkpoint and draft. Delete one supporting source after inspecting its impact: its original files and copied checkpoint evidence must disappear, comparison coverage must be labeled incomplete, and unrelated sources must remain. Restore the backup into a disposable test installation and verify the saved draft, checkpoint, quotes and original files. Shared copies are independent and cannot be remotely deleted.
16. Open My Care → Care connections. Trace a source through reviewed reports, discrepancies and follow-through; inspect its exact quotes. Compare several omitted sources, then cancel: records and reminders must remain unchanged. Switch the timeline between medical event, effective date, capture and review; missing dates must remain unknown.
17. Track a selected visit handoff, inspect and share the exact outgoing copy, and record sharing only after doing so. Finish the handoff, add and review a relevant reply, and verify the handoff flags new context without closing clinical tasks. Reopen it, create an updated copy, and recover an explicitly saved reply draft after relaunch. Repeat from an empty patient with only a saved question. Use real share destinations to verify recipient copies; the app cannot confirm delivery or acknowledgement.
18. Include a handoff and reply draft in an encrypted backup. Delete a supporting source: the cached outgoing copy must become unavailable and local staged exports must be cleared. Independently captured reply sources must survive handoff deletion. Restore the backup into a disposable installation and confirm the handoff's selected copy, sharing/finish history and draft recover together. Already shared copies cannot be recalled.
19. From both an empty patient and the synthetic demo, start an appointment companion without a known appointment date. Edit the opening, choose and rank the top three questions, enter one-question-at-a-time mode, save answers, mark discussed/ask later, pause, and reopen. After a confirmed successful save, force-quit and verify the answer, agenda order, current question, and unknown date recover. Save answers as evidence and verify only actual answer text is proposed for extraction; generated questions must not become instructions, and finishing must not complete clinical tasks. Turn Synthetic practice off for a separate real-note test using nonclinical test text: copied synthetic questions must retain their labels, mixed real/synthetic answer capture must be blocked without losing drafts, and a clean real companion must save nonsynthetic evidence.
20. Open Help me get this done for a synthetic care task. Exercise every obstacle and next action, edit the message and recipient, copy it, and share to a controlled destination; verify the received text matches the draft and no message is sent or delivery recorded merely by opening the share sheet. Record outreach and save an actual test reply; clinical stage and discrepancies must stay unchanged until appropriate review or an explicit patient-reported completion action. Choose a personal check-back time, verify the original clinical due date remains unchanged, and test notification consent/task-relevance toggles on a physical lock screen. Reminder content must remain generic; completing/dismissing the task must remove its pending personal reminder.
21. Save a follow-through message, unfinished reply, contact history, and personal check-back date. Edit supporting source text or its event date so its reviewed task disappears: the helper must remain available as a paused plan, with drafts/history intact and no active-task reminder. Review the source, explicitly reconnect to the matching current task, and confirm no automatic merging or replacement of the old message. Then delete a supporting or reply source while viewing it from the helper and return: removed copied text, recovery drafts, and sharing controls must not reappear. Repeat source deletion from a visit companion and check copied questions/answers are cleared. Verify encrypted backup/restore of successfully saved companion data in a disposable installation; separately saved reply evidence should survive helper removal. For a controlled debug save-failure test, verify prior durable data remains unchanged, follow-through autosave pauses with Retry/Discard, and changing tabs recovers its session draft. Confirm a successful retry persists before force-quit; do not treat unsaved session memory as recovery after process termination.
22. Audit Read aloud on a signed physical iPhone with an installed voice, then in airplane mode and with an unavailable language resource. Verify explicit Read aloud/Stop behavior, audible content matching the displayed opening and top three questions, readable fallback if speech fails, no microphone/recording activation, and no cloud-analysis requirement. Exercise Bluetooth/headphones, another app's audio, phone interruption, screen lock, backgrounding, and closing/changing the brief; speech must stop when the app leaves the active scene or the brief closes. Test both companions with VoiceOver and maximum Dynamic Type, including task reconnection, share destinations, character limits, and save-failure alerts. In the live visit editor's controlled debug write-failure test, verify no repeated automatic retry alerts and that Pause, question changes, and source navigation preserve the unsaved answer until a successful retry; force-quitting before that successful write is explicitly outside durable draft recovery.
